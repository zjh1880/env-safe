RULESET

九类检查，每一类都讲清"为什么"

规则集是 env-safe CLI 的超集：它额外检查连接串弱口令、未加引号的空格、小写键名，并按键名自动识别密钥字段；CLI 版则另有 --strict 与 --allow-extra。报告不只告诉你哪里错，还给出现象、风险、改法与验证方式。

01

缺失必需变量

模板里声明、运行时却没有。应用可能启动失败，或悄悄回退到默认值。

02

未声明的多余变量

团队不知道它存在，换环境容易漏配；也可能是拼写错误，实际并未生效。

03

必需变量为空

空值在多数运行时等同于未配置，鉴权或连接会直接失败。

04

占位符未替换

replace-me、dummy、dev 被当成真实密钥使用，服务鉴权失败且掩盖真问题。

05

密钥过短

低于设定长度的密钥更容易被暴力破解，泄露后的攻击成本很低。

06

示例文件写入真实值

模板会提交到仓库，真实密钥一旦进入版本历史，很难彻底清除。

07

连接串弱口令

数据库连接串里的弱口令，是配置泄露后最容易被利用的入口。

08

重复键与格式错误

后出现的值覆盖先出现的值；无法解析的行会让变量静默缺失。

09

空格与大小写

未加引号的空格、混用大小写，会让不同环境读到不同的值。

PRIVACY BY DESIGN

密钥不该离开你的设备

体检站没有后端、没有数据库、没有统计埋点。页面不加载任何外部 CDN、字体或接口，断网也能用。你粘贴的内容只存在于当前标签页的内存里，关闭页面即消失。

需要接入提交前检查或 CI 时，可以使用同一项目的命令行版本（规则集相近但并非同一份实现，差异见上文「规则」一节）：

npm install -g env-safe
env-safe check --example .env.example --env .env \
  --secret-keys JWT_SECRET --min-secret-length 12

这次体检会看什么

  • 模板与运行配置的变量差异
  • 空值、占位符与过短密钥
  • 示例文件里的真实值
  • 连接串弱口令与重复键
  • 格式错误、空格与大小写

报告可导出为 Markdown 或 JSON。导出内容只包含键名与问题描述，不会输出变量值的原文；即便如此，贴进公开 Issue 前仍建议自己通读一遍。
